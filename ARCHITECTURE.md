# APIF — System Architecture

AI Propaganda Intelligence Framework. Detects AI-generated market propaganda and verifies
genuine market communications.

Every detector returns a **Signal**; the fusion engine turns a list of Signals into a
**Verdict**. Nothing else crosses module boundaries — that single contract is what lets
detectors fail independently without taking the verdict with them.

## 2. The Signal contract

The load-bearing design decision: **an unavailable detector is excluded and the weights
renormalized — never scored 0.** A dead detector must never read as "clean."

```mermaid
flowchart LR
    subgraph sig["Signal — what every detector returns"]
        S1["name"]
        S2["score 0.0 to 1.0"]
        S3["available"]
        S4["summary"]
        S5["evidence"]
    end

    subgraph fuse["fusion.fuse()"]
        F1{"available?"}
        F2["drop from denominator"]
        F3["weight x score"]
        F4["sum / sum of weights"]
        F5{"registry-verified<br/>AND signed?"}
        F6["cap at Low"]
        F7["band by threshold"]
    end

    sig --> F1
    F1 -- "no" --> F2
    F1 -- "yes" --> F3
    F3 --> F4
    F4 --> F5
    F5 -- "yes" --> F6
    F5 -- "no" --> F7
    F6 --> F7
```

**Weights** — `text_phishing` .25 · `voice_spoof` .20 · `video_deepfake` .20 ·
`source_untrusted` .15 · `coordination` .10 · `market_anomaly` .10

**Bands** — Low < 0.30 · Medium ≥ 0.30 · High ≥ 0.60 · Critical ≥ 0.80

## 3. Request flow — audio, the most concurrent path

Ordering here is deliberate, not incidental. Media collapses to text *first* so a vishing
call and a phishing email travel the same path afterward; entity extraction runs *before*
the registry and market engines because it supplies their inputs.

```mermaid
sequenceDiagram
    autonumber
    participant C as Client
    participant P as pipeline
    participant M as media
    participant V as voice
    participant A as asr
    participant L as llm_analyst
    participant E as engines
    participant F as fusion

    C->>P: POST /verify (audio)
    P->>M: probe_duration
    M-->>P: seconds
    Note over P: reject if over cap —<br/>"safe" on unexamined media<br/>is the worst failure mode

    par spoof check and transcription overlap
        P->>V: analyze(audio)
        V->>V: transcode only if over 5MB
        V-->>P: Signal voice_spoof
    and
        P->>A: transcribe(audio)
        A-->>P: transcript
    end

    P->>L: extract_entities(caption + transcript)
    L-->>P: issuer, tickers

    par engines have their inputs now
        P->>E: trust_registry(source, issuer)
        P->>E: market(tickers)
        P->>E: text_phishing(combined)
    end
    E-->>P: Signals

    P->>F: fuse(all signals)
    F-->>P: Verdict
    P->>L: explain(verdict)
    L-->>P: plain-language explanation
    P-->>C: Verdict + evidence
```

## 4. Ingestion and coordination

Coordination is a property of a *campaign*, not of one artefact, so it is computed against
everything ingested rather than the submitted content alone.

```mermaid
flowchart LR
    subgraph sources["Sources"]
        OFF["7 official sites<br/>SEBI · NSE · BSE · press"]
        TW["X/Twitter<br/>6 search queries"]
    end

    FC["Firecrawl<br/>scrape + search"]
    DB[("SQLite<br/>content_item")]

    subgraph coord["coordination.py"]
        PARSE["parse_status_url<br/>snowflake to author + time"]
        TFIDF["TF-IDF similarity"]
        BURST["burst-window timing"]
        CLUSTER["cluster: 3+ accounts<br/>near-identical, tight window"]
    end

    OFF --> FC
    TW --> FC
    FC -->|"channel=web"| DB
    FC -->|"channel=twitter"| DB
    DB --> PARSE
    PARSE --> TFIDF
    PARSE --> BURST
    TFIDF --> CLUSTER
    BURST --> CLUSTER
    CLUSTER --> SIG["Signal coordination"]
```

Author and timestamp are recovered from the tweet URL itself — the handle sits in the
path, and the status ID is a snowflake whose upper 41 bits are a millisecond timestamp.
No Twitter API required.

## 5. Failure behaviour

What happens when each dependency is down. `degraded` means a signal is missing, not that
the service is broken.

```mermaid
flowchart TD
    START["Request arrives"] --> D{"Which dependency<br/>is unavailable?"}

    D -->|"phishing classifier"| P1["text_phishing unavailable<br/>service reports degraded"]
    D -->|"AURIGIN_API_KEY unset"| P2["voice_spoof unavailable<br/>NO fallback to local model"]
    D -->|"HF Space cold or quota"| P3["video_deepfake unavailable"]
    D -->|"no LLM key"| P4["no entities, so<br/>market_anomaly never fires"]
    D -->|"no ingested posts"| P5["coordination unavailable"]
    D -->|"media over duration cap"| P6["request REJECTED outright"]

    P1 --> R["fusion renormalizes<br/>over remaining signals"]
    P2 --> R
    P3 --> R
    P4 --> R
    P5 --> R
    R --> V["Verdict still produced<br/>with per-signal reasons"]
    P6 --> X["413 with a clear reason"]
```

The voice detector deliberately has **no fallback** to the previous local checkpoint: that
model was uncalibrated and scored genuine recordings as 100% spoof. A confidently wrong
answer is worse than an absent one.

## 6. Module layout

```
apif/
  main.py          FastAPI app, /health, 413 handler
  config.py        all tunables + .env loading
  schemas.py       Signal / Verdict — the only types crossing boundaries
  compat.py        inspect.getmodule patch for lazy ML imports; loads first
  pipeline.py      orchestration: routing, concurrency, fan-out
  detectors/       text_phishing, llm_analyst, asr, voice, video, media
  engines/         fusion, trust_registry, market, coordination
  ingest/          firecrawl, exchanges, store (SQLite)
  data/            trusted_sources.json
tests/             test_engines.py
```
